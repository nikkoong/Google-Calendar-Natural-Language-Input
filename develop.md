# Development Guide

## Project Structure

### Root Directory
```
Google Calendar Natural Language Input/
├── src/                    # Source files (edit these)
├── chrome-extension/       # Built extension (output folder)
├── tests/                  # Test files
├── scripts/                # Build scripts
├── rollup.config.improved.mjs  # Rollup bundler configuration
└── package.json           # Project dependencies and scripts
```

### Source Files (`src/`)
These are the files you edit during development:

- **`popup.js`** - Main popup UI logic
  - Handles user input for natural language events
  - Manages settings dialog and calendar nickname management
  - Quick Add button toggle control
  - Event creation and URL generation

- **`content.js`** - Content script injected into Google Calendar pages
  - Adds Quick Add button to Google Calendar UI
  - Handles button visibility based on user preferences
  - Listens for toggle messages from popup

- **`content-helpers.js`** - Natural language parsing logic
  - Uses Chrono library to parse dates/times
  - Creates Google Calendar event URLs
  - Core NLP functionality

- **`helpers.js`** - Utility functions
  - Date range formatting
  - Recurrence pattern parsing
  - Event description and location extraction
  - URL encoding and sanitization

- **`shared-utils.js`** - Shared utility functions
  - Chrome storage wrapper (ChromeStorage)
  - Calendar nickname management
  - Quick Add button visibility preferences

- **`help-content.js`** - Help dialog content (static)

- **`constants.js`** - Configuration constants

### Built Extension (`chrome-extension/`)
This folder contains the compiled extension that Chrome loads:

#### 🔨 Built Files (Generated by Rollup - DO NOT EDIT)
- **`popup.js`** - Built from `src/popup.js` (bundled with dependencies)
- **`content.js`** - Built from `src/content.js`
- **`content-helpers.js`** - Built from `src/content-helpers.js` (bundled with Chrono & dayjs)
- **`shared-utils.js`** - Built from `src/shared-utils.js`
- **`help-content.js`** - Built from `src/help-content.js`

#### ✏️ Static Files (Edit these directly in `chrome-extension/`)
- **`popup.html`** - Popup UI HTML structure and embedded CSS
- **`content.css`** - Styles for content script (Quick Add button, etc.)
- **`manifest.json`** - Extension configuration, permissions, version
- **`images/`** - Extension icon files

**⚠️ Important:** 
- Built `.js` files are overwritten by `npm run build` - edit their source files in `src/` instead
- Static files (`popup.html`, `content.css`, `manifest.json`) must be edited directly in `chrome-extension/`

### Tests (`tests/`)
- **`calendar-nlp.test.js`** - Tests for source files (NLP parsing logic)
- **`built-files.test.js`** - Tests for built files (end-to-end user experience)
- **`built-files.test.cjs`** - CommonJS version of built files tests
- **`run-tests.js`** - Test runner
- **`README.md`** - Test documentation

## Build System

### Rollup Configuration
The project uses **Rollup** to bundle source files into the `chrome-extension/` folder.

**Two types of builds:**
1. **Bundled builds** - Include external dependencies (Chrono, dayjs)
   - `popup.js` → bundles all imports
   - `content-helpers.js` → bundles Chrono and dayjs

2. **Standalone builds** - No external dependencies
   - `content.js`
   - `shared-utils.js`
   - `help-content.js`

**Output format:** IIFE (Immediately Invoked Function Expression) - works in Chrome extension environment

## Development Commands

### Build Commands

```bash
# Build the extension once
npm run build

# Build and watch for changes (auto-rebuild on save)
npm run watch
```

**What happens during build:**
- Rollup reads `src/` files
- Bundles external dependencies (Chrono, dayjs) into relevant files
- Outputs compiled files to `chrome-extension/`
- Takes ~200-500ms total

### Testing Commands

```bash
# Run source file tests (tests NLP parsing logic)
npm test

# Run built files tests (tests actual extension files)
npm run test:built

# Run all tests (source + built)
npm run test:all

# Watch mode - auto-run tests when files change
npm run test:watch
```

**Test Coverage:**
- ✅ Date parsing (various formats)
- ✅ Event descriptions with `d()` syntax
- ✅ Event locations with `l()` syntax
- ✅ Recurrence patterns (daily, weekly, monthly, yearly)
- ✅ Multiple events with semicolons
- ✅ Calendar targeting with `@nickname`
- ✅ Input sanitization and validation
- ✅ End-to-end URL generation

See `tests/README.md` for detailed test documentation.

## Local Testing Workflow

### 1. Make Code Changes

**For JavaScript logic** - Edit files in `src/` directory:
```bash
# Example: editing popup logic
code src/popup.js
```

**For UI/styles/config** - Edit files in `chrome-extension/` directory:
```bash
# Example: editing popup HTML or styles
code chrome-extension/popup.html

# Example: editing Quick Add button styles
code chrome-extension/content.css

# Example: changing extension version or permissions
code chrome-extension/manifest.json
```

### 2. Build the Extension (if needed)

**Only needed if you edited `src/` files:**
```bash
npm run build
```
Or use watch mode for automatic rebuilds:
```bash
npm run watch
```

**Not needed if you only edited:**
- `chrome-extension/popup.html`
- `chrome-extension/content.css`
- `chrome-extension/manifest.json`
- `chrome-extension/images/`

### 3. Load Extension in Chrome

#### First time setup:
1. Open Chrome and go to `chrome://extensions/`
2. Enable **Developer mode** (toggle in top right)
3. Click **Load unpacked**
4. Select the `chrome-extension/` folder
5. Note the extension ID for future reference

#### After making changes:
1. Build the extension: `npm run build`
2. Go to `chrome://extensions/`
3. Click the **reload icon** on your extension card
4. Test your changes!

### 4. Test Your Changes

**Test the popup:**
- Click the extension icon in Chrome toolbar
- Or press `Cmd+E` (Mac) / `Ctrl+E` (Windows/Linux)
- Try entering natural language events

**Test the Quick Add button:**
1. Go to [Google Calendar](https://calendar.google.com)
2. Open extension settings (click icon → ⚙️ button)
3. Toggle "Show Quick Add button"
4. Verify button appears/disappears next to Create button

**Test calendar nicknames:**
1. Open extension settings
2. Add a nickname like `@work` with your calendar ID
3. Create an event: "Meeting tomorrow 2pm @work"
4. Verify it opens with the correct calendar selected

### 5. Run Tests
```bash
# Quick test during development
npm test

# Full test before committing
npm run test:all
```

## Common Development Tasks

### Adding a New Feature

1. **Edit source file** in `src/`
2. **Add tests** in `tests/calendar-nlp.test.js` or `tests/built-files.test.js`
3. **Run tests** to verify: `npm test`
4. **Build**: `npm run build`
5. **Test in Chrome** by reloading extension
6. **Run full test suite**: `npm run test:all`

### Fixing a Bug

1. **Write a failing test** that reproduces the bug
2. **Fix the bug** in `src/` files
3. **Verify test passes**: `npm test`
4. **Build and test in browser**: `npm run build`
5. **Check for regressions**: `npm run test:all`

### Modifying the UI

**Popup UI:**
- HTML: Edit `chrome-extension/popup.html` directly ✏️ (static file)
- CSS: Edit styles directly in `chrome-extension/popup.html` `<style>` tag ✏️
- JavaScript: Edit `src/popup.js` then build 🔨
- After changes: Run `npm run build` and reload extension

**Quick Add button UI:**
- Styles: Edit `chrome-extension/content.css` directly ✏️ (static file)
- Logic: Edit `src/content.js` then build 🔨
- After changes: Run `npm run build` and reload extension

**Extension Settings:**
- Version, permissions, commands: Edit `chrome-extension/manifest.json` directly ✏️
- After changes: Reload extension (no build needed)

### Debugging Tips

**Console Logging:**
```javascript
// In popup.js
console.log('Popup:', data);

// In content.js
console.log('Content Script:', data);
```

**View logs:**
- **Popup logs**: Right-click extension icon → Inspect popup
- **Content script logs**: Open DevTools on Google Calendar page → Console tab

**Chrome Storage Inspection:**
```javascript
// In popup or content script
chrome.storage.sync.get(null, (data) => console.log('Storage:', data));
```

**Common Issues:**
- Extension not updating? → Reload extension in `chrome://extensions/`
- Content script not working? → Refresh Google Calendar page
- Storage not persisting? → Check Chrome sync is enabled

## File Dependency Map

### Popup Files
```
popup.html
  └─ popup.js (built)
      └─ src/popup.js
          ├─ helpers.js → content-helpers.js (bundled with Chrono/dayjs)
          └─ shared-utils.js
```

### Content Script Files
```
manifest.json
  └─ content_scripts (injected on calendar.google.com)
      ├─ shared-utils.js
      ├─ help-content.js
      ├─ content-helpers.js (bundled with Chrono/dayjs)
      ├─ content.js
      └─ content.css
```

### Storage Structure
```javascript
chrome.storage.sync = {
  quickAddButtonVisible: boolean,  // Quick Add button visibility (default: false)
  savedCalendars: {                // Calendar nickname mappings
    '@work': 'john.doe@company.com',
    '@personal': 'john.doe@gmail.com'
  }
}
```

## Publishing Updates

### 1. Update Version
Edit `package.json` and `chrome-extension/manifest.json`:
```json
{
  "version": "2.4.0"
}
```

### 2. Build Production Version
```bash
npm run build
```

### 3. Run Full Test Suite
```bash
npm run test:all
```

### 4. Create Zip File
Zip the contents of the `chrome-extension/` folder:
```bash
cd "Google Calendar Natural Language Input"
zip -r extension-v2.4.0.zip chrome-extension/
```

### 5. Upload to Chrome Web Store
1. Go to [Chrome Developer Dashboard](https://chrome.google.com/webstore/devconsole)
2. Select your extension
3. Upload the zip file
4. Submit for review
